# Каналы: сайты, ВК, RuStore

Один и тот же код обслуживает три канала. Ниже — что готово, что нужно
сделать и что зависит не от нас.

Домены клубов (подтверждены заказчиком 2026-09-09):
**https://effectvr.ru** и **https://vrayarena.ru**. Оба уже перечислены в
`frame-ancestors` (`web/_headers`, `web/.htaccess`) вместе с поддоменами
`*.effectvr.ru` / `*.vrayarena.ru`, так что `www` тоже разрешён.

---

## 1. Сайты клубов — iframe

**Статус:** код готов, нужен хостинг.

Виджет живёт на одном поддомене и встраивается в оба сайта. Дублировать
установку не надо: обновили в одном месте — обновилось везде.

### Что нужно от инфраструктуры

1. Поддомен с HTTPS, например `book.effectvr.ru` (годится любой из двух доменов —
   виджет обслуживает оба клуба).
2. Доступ, чтобы залить туда содержимое `build/web`.
3. `.htaccess` (Apache) или блок из `docs/DEPLOY.md` (nginx) — без них не
   заработают `frame-ancestors` и кэш-политика.

### Код для вставки

На сайт **Effect VR** (`effectvr.ru`):

```html
<iframe id="vr-booking"
        src="https://book.effectvr.ru/?club=effect&source=site"
        style="width:100%;max-width:480px;border:0;display:block;margin:0 auto;height:680px"
        loading="lazy"
        title="Онлайн-бронирование Effect VR"></iframe>
<script>
  (function () {
    var frame = document.getElementById('vr-booking');
    var ORIGIN = 'https://book.effectvr.ru';
    window.addEventListener('message', function (e) {
      if (e.origin !== ORIGIN) return;          // чужие сообщения игнорируем
      var m = e.data || {};
      if (m.type === 'vr-booking:height' && m.height) {
        frame.style.height = m.height + 'px';   // фрейм тянется по контенту
      }
      if (m.type === 'vr-booking:success') {
        // цель в Метрике: ym(XXXXXX, 'reachGoal', 'booking');
      }
    });
  })();
</script>
```

На сайт **V-Ray** (`vrayarena.ru`) — то же самое, но `?club=vray` и заголовок
«Онлайн-бронирование V-Ray».

`?club=` фиксирует клуб: мастер сокращается с четырёх шагов до трёх, выбор
клуба не показывается.

## 2. ВК

**Статус:** нужно решение, какой формат.

Важно: **произвольный iframe в виджет сообщества ВК вставить нельзя** — там
фиксированный набор типов виджетов (обложка, список, таблица…). Поэтому
вариантов два.

### Вариант А. Ссылка из сообщества (готово сегодня)

Кнопка действия сообщества или ссылка в меню ведёт на
`https://book.effectvr.ru/?club=effect&source=vk`. Работает прямо сейчас,
делать нечего — только настроить сообщество. `source=vk` попадёт в
`booking_orders.source`, и в статистике будет видно, откуда пришла бронь.

### Вариант Б. VK Mini App

Полноценное приложение внутри ВК: открывается в мобильном приложении и на
сайте, живёт в каталоге приложений.

Что нужно:

1. Зарегистрировать приложение на `vk.com/editapp?act=create` (тип «Веб-сайт» /
   Mini App), указать адрес поддомена.
2. ВК открывает приложение в своём iframe — `frame-ancestors` уже содержит
   `*.vk.com`, `*.vk.ru`, `*.vk-apps.com`, так что тут готово.
3. Виджет уже понимает, что открыт из ВК: `LaunchParams` определяет `source=vk`
   по параметру `vk_app_id`, который ВК добавляет сам.
4. **VK Bridge — отдельная работа.** Без него всё работает, но клиент вводит имя
   и телефон руками. С ним можно запросить их из профиля (`VKWebAppGetUserInfo`,
   `VKWebAppGetPhoneNumber`) и подставить в форму. Это плюс к конверсии, но
   требует подключения JS-моста и разрешений приложения.

Рекомендация: начать с варианта А (ноль работы), а Mini App делать, когда
виджет обкатается на сайтах.

## 3. RuStore — Android-приложение

**Статус:** проверено, собирается. Нужны решения и аккаунт разработчика.

Платформа Android добавлена (`flutter create --platforms=android --org ru.effectvr`),
release-сборка проходит: **18,2 МБ**. Код Dart переиспользуется целиком —
веб-специфичные части (`localStorage`, `postMessage`, переход в админку) уже
были за условными импортами и на Android подставляют заглушки.

### Что уже сделано

* `INTERNET`-разрешение в основном манифесте. Flutter кладёт его только в
  debug/profile — без правки release-сборка молча не смогла бы обратиться к
  Supabase: ни клубов, ни слотов, ни отправки брони.
* Название приложения — «Бронирование VR».
* Служебный вход «Для сотрудников» скрыт вне веба: админка живёт по адресу
  `?admin=1`, которого в приложении нет.

### Соответствие требованиям RuStore

Проверено на собранном артефакте (`aapt2 dump badging`):

| Требование RuStore | У нас | |
|---|---|---|
| `targetSdkVersion` ≥ 28 | **36** | ✅ |
| 64-битные библиотеки | `arm64-v8a`, `armeabi-v7a`, `x86_64` | ✅ |
| Формат `.aab` или `.apk` | оба собираются | ✅ |
| Подпись ключом RSA ≥ 2048 бит | конфиг готов, ключ создаёт владелец | ⏳ |
| `packageName` совпадает с листингом | `ru.effectvr.vr_booking_web` | ⏳ выбрать финальный |

Размеры: APK со всеми архитектурами — **51,5 МБ**, AAB — **50,5 МБ**.
Загружать в RuStore лучше AAB: витрина сама нарежет сборку под устройство, и
пользователь скачает около 18 МБ вместо пятидесяти.

### На каких устройствах запустится

`minSdkVersion` — **24**, то есть **Android 7.0 Nougat и новее**. Это значение
Flutter задаёт сам, и понижать его не стоит: более старые версии фреймворк
официально не поддерживает.

Что это значит на практике: Android 7.0 вышел в 2016 году, и устройства
старше него — это телефоны 2014–2015 годов. Их доля в живой аудитории уже
единицы процентов, и почти все они не потянут VR-клуб как аудиторию.

Три архитектуры покрывают всё, что встречается: `arm64-v8a` — современные
телефоны, `armeabi-v7a` — старые 32-битные, `x86_64` — эмуляторы и редкие
планшеты на Intel.

Разрешение у приложения ровно одно — **`INTERNET`**. Ни камеры, ни геолокации,
ни контактов: при установке система ничего не спросит, а на модерации не будет
вопросов «зачем вам это». Отдельных требований к экрану или железу нет,
интерфейс уже проверен на ширине от 360 px.

### Подпись

Конфигурация готова: `android/app/build.gradle.kts` читает `android/key.properties`,
а если файла нет — собирает debug-ключом, чтобы сборка не падала у того, у кого
ключа нет. Шаблон — `android/key.properties.example`, сам ключ и пароли в
`.gitignore`.

**Ключ создаёт владелец приложения, не разработчик и не я.** Команда:

```bash
keytool -genkey -v -keystore vr-booking-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias vr-booking
```

RSA 2048 — минимум, который принимает RuStore. Дальше скопировать
`key.properties.example` в `key.properties` и вписать пути и пароли.

⚠️ **Потеря ключа необратима.** Обновить опубликованное приложение будет нечем:
придётся publish новое с другим `applicationId`, потеряв установки и отзывы.
Копию `.jks` и паролей — в надёжное место, не в репозиторий.

### Что ещё нужно

| Шаг | Комментарий |
|---|---|
| Финальный `applicationId` | После публикации не меняется |
| Аккаунт разработчика | Требуется ИП или юрлицо |
| Скриншоты и описание | Минимум для карточки |
| Политика конфиденциальности | Обязательна: собираем имя и телефон |

### О чём подумать до публикации

Сейчас приложение — это ровно тот же экран бронирования. Чтобы оно оправдывало
установку, стоит добавить хотя бы одно из:

* **push-напоминание о сеансе** — главный аргумент «зачем ставить приложение»;
* историю посещений и повтор брони в один тап (данные уже хранятся локально);
* карту и телефон клуба на видном месте.

Иначе пользователь резонно спросит, чем это лучше сайта.

## Порядок, который предлагается

1. Поддомен + заливка → работают оба сайта.
2. Ссылка из сообществ ВК (`source=vk`) → канал открыт в тот же день.
3. Смотрим статистику: если из ВК идёт заметный поток — делаем Mini App с
   VK Bridge.
4. RuStore — когда будет решено, чем приложение полезнее сайта.
