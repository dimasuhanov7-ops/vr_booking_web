# Зеркало броней: Google Таблица + Telegram

Каждая новая бронь, отмена и правка сама попадает в Google Таблицу и приходит
сообщением в служебный Telegram-чат. Источник не важен: сайт, ВК, приложение
или админка.

## Как устроено

```
booking_orders ──триггер──▶ pg_net ──▶ Edge Function booking-mirror ──▶ Apps Script в таблице
                                                                   └──▶ Telegram
pg_cron, 03:00 по Перми ──▶ booking-mirror {"mode":"resync"} (досинхронизация)
```

* Бронь клиента **не ждёт** Google и Telegram и не падает, если они недоступны.
* Функция берёт из вызова только id заказа и сама перечитывает его из базы.
  Вызов функции подписан секретом из Vault (`booking_mirror_secret`) — его
  генерирует база, вводить не нужно.
* Таблицу ведёт **Apps Script внутри самой таблицы** (Google Cloud не нужен).
  Скрипт принимает строки только с правильным секретом, берёт блокировку
  (одновременные вызовы не дают дублей) и пишет «формулы» из имён клиентов
  как текст.
* В таблице одна строка на заказ; при отмене или правке строка обновляется.
  Ночью всё, что не доехало, дописывается, лишние дубли удаляются.
* Об одном и том же статусе в Telegram пишется один раз (`booking_mirror_state`).
* Google изредка отвечает на вызов скрипта 404 (сам скрипт при этом рабочий).
  Функция повторяет запись ещё дважды — через 2 и 6 секунд; если не вышло,
  строку поправит ночная досинхронизация.

Файлы: миграция `supabase/migrations/20260915081448_online_booking_mirror.sql`,
функция `supabase/functions/booking-mirror/index.ts`,
скрипт таблицы `tool/google_apps_script/booking_mirror.gs`.

## Стоимость в таблице и Telegram

Цена пакета, если бронь по пакету, иначе сумма `booking_order_items.price`;
затем минус промокод (`booking_orders.discount_id` → `booking_discounts`):
процент от этой суммы с округлением до рубля, фиксированная скидка — не больше
суммы. Так же считают виджет и админка. Отдельной колонки под скидку нет —
код пишется к составу («…; промокод VRPARTY −10%»), в Telegram — рядом с суммой.
Промокоды — с `booking-mirror` v10 (24.09).

## Что нужно настроить (один раз)

Секреты, токены и адрес скрипта вводит владелец. Не пересылайте их в чаты и не коммитьте.

### 1. Google Таблица и скрипт

1. Создайте таблицу: https://sheets.new (под аккаунтом клуба).
2. В таблице: **Расширения → Apps Script**.
3. Удалите весь код в редакторе и вставьте содержимое файла
   `tool/google_apps_script/booking_mirror.gs`. Нажмите значок дискеты (Сохранить).
4. Вверху в списке функций выберите **`setupSecret`** → **Выполнить**.
   * Google попросит разрешения: «Проверить разрешения» → выберите аккаунт.
   * Появится предупреждение «Приложение не проверено» — это ваш собственный
     скрипт: «Расширенные настройки» → «Перейти к проекту (небезопасно)» → «Разрешить».
5. Внизу откроется **Журнал выполнения** со строкой
   `GOOGLE_SCRIPT_SECRET = …` — скопируйте значение после `=`.
6. **Развернуть → Новое развертывание** → шестерёнка «Выберите тип» →
   **Веб-приложение**:
   * «Выполнять от имени» — **Я**;
   * «У кого есть доступ» — **Все**;
   * **Развернуть** → скопируйте **URL веб-приложения** (оканчивается на `/exec`).

«Доступ: Все» нужен, чтобы Supabase мог достучаться до скрипта без входа в
Google. Без секрета скрипт ничего не принимает, а читать таблицу по этой
ссылке нельзя.

### 2. Telegram

1. В Telegram откройте **@BotFather** → `/newbot` → получите токен бота.
2. Добавьте бота в группу персонала.
3. Напишите в группе любое сообщение, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":…}`.
   У групп id отрицательный, например `-1001234567890`.

### 3. Секреты в Supabase

Supabase → проект «Vray/Effect info» → **Edge Functions → Secrets** → добавьте:

| Имя | Значение |
|---|---|
| `GOOGLE_SCRIPT_URL` | URL веб-приложения из п. 1.6 |
| `GOOGLE_SCRIPT_SECRET` | секрет из п. 1.5 |
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | id чата |
| `TELEGRAM_THREAD_ID` | *(необязательно)* id темы, если в группе включены темы |

В группе с темами без `TELEGRAM_THREAD_ID` сообщения идут в «General». Чтобы
получать их в отдельной теме: создайте тему (например, «Брони»), напишите в ней
`/start@имя_бота`, обновите `getUpdates` и возьмите `"message_thread_id"`.

Без Google-секретов таблица не ведётся, без Telegram-секретов не приходят
уведомления: одно работает без другого.

### 4. Первая заливка

После секретов выполните в SQL-редакторе Supabase (или попросите разработчика):

```sql
select public.booking_mirror_call('{"mode":"resync"}'::jsonb);
```

Через несколько секунд в таблице появится лист «Брони» со всеми существующими
бронями. Уведомления в Telegram придут для новых броней — старые в чат не рассылаются.

## Правила для персонала

* Таблица — **копия только для чтения**. Правки в ней перезапишутся при
  следующем изменении брони или ночью. Меняйте брони в админке.
* Сортировать, фильтровать и скрывать колонки можно. Нельзя удалять колонку
  «ID заказа» и переименовывать лист «Брони».
* В таблице телефоны клиентов — давайте доступ только тем, кому он нужен.

## Обслуживание

* Поменяли код скрипта → **Развернуть → Управление развертываниями** →
  карандаш → «Версия: новая» → «Развернуть». Иначе работает старая версия.
  URL при этом не меняется.
* Секрет скрипта утёк → снова запустите `setupSecret` и обновите
  `GOOGLE_SCRIPT_SECRET` в Supabase.
* Логи функции: Supabase → Edge Functions → `booking-mirror` → Logs
  (без имён и телефонов). Логи скрипта: Apps Script → «Выполнения».
* Статус вызовов из базы:
  `select status_code, content, created from net._http_response order by created desc limit 20;`
