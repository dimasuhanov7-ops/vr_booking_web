### Админка (сделано 24.09)

- **Новая запись** создаёт бронь в БД через `booking_create_order` (от
  сотрудника: без лимитов и паузы, `source=staff`); кнопка блокируется, пока
  запрос идёт, — дублей нет.
- **Карточка брони**: имя/телефон/предоплата/комментарий по «Сохранить»;
  **перенос и смена состава** — через `booking_reschedule_order` (атомарно:
  старые позиции удаляются, новые вставляются с теми же проверками, что при
  создании; пересечение → 23P01, бронь остаётся как была; уже начавшийся
  сеанс можно продлить/сократить; неподходящий пакет снимается).
- **Визит**: «ждём / пришёл / не пришёл» → `status` `confirmed` / `completed`
  / `no_show`; не пришедшие приглушены в сетке, в KPI дня — «N не пришли».
- **Поиск** по имени и телефону (цифры в любом формате) во вкладке «Записи» —
  по всем клубам и датам; результат открывает карточку в нужном клубе и дне.
- **Realtime**: канал `admin-bookings` на `booking_orders`, `…_order_items`,
  `…_availability`, `booking_clubs` (публикацию включает `admin_realtime`);
  пачка событий → одно перечитывание через 600 мс; раз в минуту — страховочное
  перечитывание. Несохранённые правки не затираются.
- **Журнал** (вкладка): `booking_audit_log` по-русски — цены, пакеты,
  доступность, клуб, статусы и переносы броней, промокоды.
- **Промокоды** (карточка во вкладке «Цены»): завести (код, % или ₽, «от N
  мест»), выключить, удалить; код с бронями не удаляется, а выключается.
  Скидка входит в стоимость брони в карточке и в сумму дня: сначала пакет
  (или почасовая), потом промокод от этой суммы; процент округляется до рубля,
  фиксированная сумма не больше базы — так же считают виджет и `booking-mirror`.
- Вход проверяет `booking_is_staff()`; ошибка загрузки — экран с
  «Повторить»/«Выйти»; пакет с бронями выключается вместо удаления (нейтральная
  плашка-пояснение, не ошибка).

## Что это

Отдельный **публичный Flutter Web виджет онлайн-бронирования** VR-клубов
**Effect VR** и **V-Ray**. Встраивается iframe'ом в сообщество ВК и на сайт клуба,
без авторизации персонала. Backend — тот же Supabase, что и у внутреннего
менеджера, но новые таблицы (см. ниже).

Это **не** внутренний менеджер персонала. Тот — отдельное приложение в
`C:\Users\User\Downloads\vr_club_app\vr_club_app` (плоская структура, не трогать).

## Решения заказчика (зафиксированы)

| Тема | Решение |
|---|---|
| Длительности сеанса | **60 / 120 / 180 / 240** мин (1,5 ч нет, есть 4 ч). Зашито в RLS/RPC — миграция `20260907120000_online_booking_durations`. Про шаг сетки стартов — строка «Сетка времени». |
| Цены | В БД (`booking_prices`), редактируются из админки. На проде (24.09): VR **800 ₽/ч** будни / **1200 ₽/ч** выходные; PS5 **300** / **400**. Одинаково для обоих клубов. Возможны ступени «от N станций» (`min_qty`). Оплата на месте, суммы в виджете справочные. |
| Залы V-Ray | «Большой зал» (12 VR), «Малый зал» (4 VR + 2 PS5) + вариант **«Весь клуб»** — одна бронь на станции из обоих залов. Effect VR — один зал «Зал» (4 VR + 2 PS5). |
| Часы | Effect **11:00–22:30**, V-Ray **11:00–23:00**, TZ **Asia/Yekaterinburg** (Пермь, UTC+5; до 2026-09-10 в БД ошибочно стояла Москва). |
| Закрытие записи | **За 30 минут до начала** сеанса. Сервер: `TOO_LATE_TO_BOOK` для клиентов, персонал записывает и позже. Виджет: такие слоты не показывает (`SlotGeneratorService.bookingLead`). |
| Большой зал V-Ray | Два ряда по 6 шлемов — «половины арены»; на телефоне каждая половина блоком 3×2 с кнопкой «взять половину». |
| Пакеты | Цена за состав на фиксированную длительность, не зависит от дня. Карточки показываются **только на свою длительность** (пакет на 2 часа не виден при сеансе на 1 час) — вместо них подсказка «Пакеты есть на 2 ч». **Клиент не должен переплачивать:** если выбранный руками состав совпал с пакетом, который дешевле, чем по часам, цена пакетная автоматически (`PackageAdvisorService.priceFor`, `QuoteEntity.packageId` уходит в заявку). Над «Забронировать» — подсказка, если пакет побольше той же длительности стоит не дороже текущего итога («6 шлемов выйдет дешевле»); «Взять» оставляет выбранные места и добирает рядом (`BookingPackageUpgraded`, `StationPickerService.extend`). Выбранная карточкой пакета цена применяется, даже если дороже почасовой. |
| Сетка времени | Старты — **часовые** (час + пауза клуба) при любой длительности: сеанс на 2 часа можно начать в 12:10, а не только в 11:00 и 13:10 (`SlotGeneratorService`). Сервер к сетке не привязан — проверяет часы работы, пересечения и закрытия. |
| Ступени цены | «До 6 шлемов одна цена, от 7 — другая». Цена ступени применяется **ко всем шлемам сразу** (8 × 700, а не 6 × 800 + 2 × 700) — решение заказчика 2026-09-16. Хранится в `booking_prices.min_qty`, считается и на сервере (`booking_station_price(…, p_qty)`), и в виджете. Ступеней может быть несколько («от 6 — 700 ₽, от 9 — 600 ₽»): берётся самая высокая подходящая. В админке — список ступеней шлемов (порог, цены будни/выходные, удалить, «+ Добавить ступень»); сохраняется целиком через `saveVrTiers`. |
| Скидки | **Пока без UI.** Инфраструктура в БД (`booking_discounts`, RPC `booking_validate_discount`) оставлена на будущее, данных нет, поле промокода в виджете не показывается. |
| Выходные | сб + вс (по дате брони в TZ клуба). |

### Flutter
Слои `data / domain / presentation` в `lib/features/booking/` по стандартам Friflex.
`flutter analyze` — чисто, `flutter test` — 3 теста проходят,
`flutter build web` собирается.

**Android — два приложения из одного кода** (флейворы в `android/app/build.gradle.kts`):

| Приложение | Команда | Файл |
|---|---|---|
| «Бронирование VR» (клиенты, RuStore) | `flutter build apk --release` | `app-client-release.apk` |
| «VR Админка» (персонал, ставится вручную) | `flutter build apk --release --flavor staff -t lib/main_staff.dart` | `app-staff-release.apk` |

Админка — временная, до переноса онлайн-броней в приложение-менеджер. У неё свой
`applicationId` (`…vr_booking_web.staff`) и янтарная иконка (`tool/make_icons.py`),
на одном телефоне оба приложения стоят рядом. Войти может только пользователь
Supabase Auth, добавленный в `booking_staff`.

**Админка обновляется сама** (с 2026-09-18): изменения `booking_orders`,
`booking_order_items`, `booking_availability`, `booking_clubs` приходят через
Supabase Realtime (миграция `20260920120000`, доставка по RLS — только
сотрудникам), пачка событий склеивается в одно перечитывание за 0,7 с.
Своё закрытие времени перечитывается сразу, при возврате в приложение — тоже.
Минутное автообновление осталось запасным.

**«Новая запись» в админке сохраняется в БД** (с 2026-09-10; раньше жила только
в памяти). Состав задаётся по залам — одной бронью можно занять места в обоих
залах V-Ray. Станции подбирает `AdminStationAllocator` по серверной занятости
(компактно, гость не пересаживается между часами) и шлёт `booking_create_order`
с `source = staff`. В журнале бронь на два зала — строка на зал с общим
`orderId`; отмена любой строки снимает весь заказ. Без телефона пишется
«не указан» (в БД поле обязательное).

**Аудит админки (2026-09-10).** Права проверены действием в транзакциях с откатом
под тремя ролями: гость и сотрудник менеджера без `booking_staff` не читают брони
и ничего не меняют (42501 / 0 строк, выдать себе доступ нельзя); сотрудник
бронирования не может удалить заказ, подменить станции, переписать аудит-лог или
выдать доступ другому. Исправлено по итогам:

  (RLS молча отбрасывал чужие правки — экран показывал мнимый успех);

**Все миграции применены, Edge Function задеплоена (v3).** База

> их повторно. Новые миграции применять через MCP или SQL Editor.

Проверено на проде живыми запросами:

| Проверка | Результат |
|---|---|
| `GET /clubs`, `GET /packages` | 200, сид на месте |
| Прямой `INSERT` анонимом в `booking_orders` | `42501 permission denied` |

| Пустой `segments` | `NO_STATIONS` 422 |

и `?duration=120`, пакеты и тарифы приходят из БД.
